## 0. 为什么现在停下来补设计

链路已经跑通：导入渲染 → 同步妙搭 → 应用内选片（webview 已内嵌，扫码登录正常）→ 本地组合导出。**功能不缺，缺的是"这看起来不像个产品"**。

当前界面的问题（对着截图逐条）：

1. **气质错位**：深色 `#0e1116` + 顶部灰到看不清的路径 + 底部一大块空的"运行日志"黑框 —— 整体是"开发者调试台"，不是给客户看的东西。
2. **信息层级混乱**：第 1、2 步两张卡宽度不齐、挤在顶部；第 4 步又单独占一行；圆圈数字步骤条生硬。
3. **选片区最伤**：把飞书**整张登录页**（含右侧"先进团队 先用飞书"营销插画）裸嵌进来，占掉大半屏又没有自己的设计；工具条上那条超长 `accounts.feishu.cn/...` URL 像个 bug。
4. **没有"空 / 加载 / 成功 / 失败"的状态设计**：全靠底部日志文本流表达，客户看不懂。

再往后堆功能，这套交互骨架就定死了、难改。所以**这一版只做设计 + 外壳，不加新功能**。

## 1. 产品需求（PRD）

### 1.1 一句话定位

> 一个**本地优先**的 PPT 页库控制台：把散落的历史 PPTX 拆成"页"沉淀下来，在应用内挑选、再组合导出成新 PPTX。源文件永远只在本地，妙搭只承载缩略图和元数据用于在线浏览选片。

### 1.2 目标用户 & 场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 主用户（你自己 / 小团队） | 做豆包工作 / 组织文化的对外分享，反复"从旧材料里�scavenge好页" | 快速找到好页、按叙事顺序拼成新 deck |
| 观众（同事 / 客户） | 看你演示这个工具本身 | 一眼看懂"它在干嘛"，界面不掉价 |

### 1.3 核心用户故事

1. 作为主用户，我把几个历史 PPTX 拖进来，系统自动拆页、分类、出缩略图，这样我不用手动翻源文件。
2. 作为主用户，我在一个**网格视图**里浏览所有页的缩略图，按主题 / 类型筛选、搜索关键词，快速定位候选页。
3. 作为主用户，我**多选**若干页、**拖动排序**成我想要的叙事顺序，导出一份选片清单。
4. 作为主用户，我一键把选片组合成新 PPTX，源页面**保真**（不是重新渲染的图片，是原生 OOXML 复制）。
5. 作为观众，我在旁边看，能看懂每一步在干嘛、进度到哪、成没成功。

### 1.4 功能范围（本轮）

**做（In scope）**：

- 客户端**外壳整体重设计**：布局、配色、组件、状态设计、文案。
- 四步主流程的**视觉与交互重构**（导入渲染 / 同步妙搭 / 选片 / 组合导出）。
- 选片区**收口**：不再裸嵌飞书登录页，做成"干净地承载妙搭页 + 清晰引导 + 状态反馈"。
- **选片体验重构的设计稿**（妙搭前端网格选片 UI + 导出清单回传），作为独立交付线。

**不做（Out of scope，本轮）**：

- 不新增业务功能（不加批注、协作、版本对比等）。
- 不改本地 `pptlib` 的解析 / 渲染 / 组合内核逻辑。
- 妙搭前端的**代码落地**不在本轮承诺内（受账号限制，见 §4）。

### 1.5 成功标准

- 打开客户端，**不看文档也能明白**四步在做什么、现在能点哪一步。
- 选片区第一屏不再是"别人的登录页占满屏"，而是有引导、有边界、有状态的自有设计。
- 任意一步的**进行中 / 成功 / 失败 / 空**都有明确的视觉反馈，不依赖底部日志。
- 截图发群里，同事第一反应是"这是个产品"，不是"这是个脚本 GUI"。

## 2. UI/UX 设计规范（飞书 / Lark 浅色原生风）

### 2.1 设计基调

克制、清晰、留白充足。信息密度高但不拥挤。**内容是主角，chrome（框架装饰）退到背景**。参考飞书文档 / 飞书妙搭本身的浅色界面质感。

### 2.2 设计 Token

**配色（浅色）**

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#F5F6F7` | 页面背景（飞书灰白） |
| `--surface` | `#FFFFFF` | 卡片 / 面板背景 |
| `--surface-hover` | `#F2F3F5` | hover 态 |
| `--border` | `#E5E6EB` | 分隔线 / 卡片描边 |
| `--text-primary` | `#1F2329` | 主文本（飞书近黑） |
| `--text-secondary` | `#4E5969` | 次要文本 |
| `--text-tertiary` | `#8F959E` | 辅助 / 占位 |
| `--brand` | `#3370FF` | 飞书主蓝（主按钮 / 链接 / 选中） |
| `--brand-hover` | `#245BDB` | 主蓝 hover |
| `--brand-light` | `#E8F0FF` | 主蓝浅底（选中卡片 / tag） |
| `--success` | `#00B42A` | 成功 |
| `--warning` | `#FF7D00` | 警告 |
| `--danger` | `#F53F3F` | 错误 |

**字体**

- 中文：`PingFang SC`；英文 / 数字：`-apple-system`；等宽：`SF Mono`
- 字号：标题 `16/20px`、正文 `14px`、辅助 `12px`
- 行高：正文 `1.6`

**圆角 / 阴影 / 间距**

- 圆角：卡片 `8px`、按钮 / 输入 `6px`、缩略图 `4px`
- 阴影：卡片 `0 1px 3px rgba(0,0,0,.06)`；浮层 `0 4px 16px rgba(0,0,0,.1)`
- 间距基数：`4px`，常用 `8 / 12 / 16 / 24`
- 主内容最大宽度 `1080px`，两侧留白

### 2.3 整体布局（从"四张卡"改成"左导航 + 主工作区"）

当前是四张卡平铺 + 底部日志，凌乱。改成经典的**左侧步骤导航 + 右侧主工作区**：

```
┌──────────────────────────────────────────────────────────┐
│  顶部栏：产品名 + 环境/仓库状态（一行，克制）              │
├───────────────┬──────────────────────────────────────────┤
│  左侧导航      │  主工作区（当前步骤的内容占满）            │
│  ① 导入渲染    │                                          │
│  ② 同步妙搭    │   [ 当前步骤的卡片 / 网格 / webview ]     │
│  ③ 选片        │                                          │
│  ④ 组合导出    │                                          │
│               │                                          │
│  ──────────    │                                          │
│  运行日志      │  ← 折叠进底部抽屉，默认收起               │
└───────────────┴──────────────────────────────────────────┘
```

- **左侧导航**：四步竖排，带状态点（灰=未开始 / 蓝=进行中 / 绿=完成）。点击切换主工作区。
- **主工作区**：一次只专注一步，信息不再互相挤。
- **运行日志**：从"永远占底部一大块黑框"改成**底部可折叠抽屉**，默认收起，需要时展开看细节。演示时保持干净。

### 2.4 关键界面：选片区（重点整改）

这是最丑的地方，分两层设计：

**A. 客户端承载层（本轮就能做）**

- 不再让飞书登录页裸占满屏。webview 外面包一层**自有的容器 + 引导条**：
  - 顶部一条**极简工具条**：`← 后退` / `刷新` / `在浏览器打开`，URL 只显示域名（`bytedance.feishuapp.cn`），不再铺整条超长 URL。
  - **未登录态**：webview 上盖一层浅色引导卡 —— "首次使用请在下方登录飞书，登录态会保留" + 一个明确的登录说明，而不是让用户对着裸登录页猜。
  - **已登录 / 选片中**：webview 干净铺满容器，边框收口成卡片。
  - webview 容器高度自适应，配一个浅色占位骨架（加载时）。

**B. 妙搭选片前端层（独立交付线，需改妙搭 → 见 §4）**

真正的选片体验应该是**缩略图网格**，而不是现在这样"能看到啥算啥"：

```
┌─────────────────────────────────────────────┐
│  筛选：[主题▾] [类型▾]   搜索：[_________]   │
├─────────────────────────────────────────────┤
│  ▢缩略图  ▢缩略图  ▢缩略图  ▢缩略图         │  ← 多选，选中打勾+蓝框
│  ▢缩略图  ▢缩略图  ▢缩略图  ▢缩略图         │
│  ...                                        │
├─────────────────────────────────────────────┤
│  已选 6 页  [清空]        [导出选片清单 →]   │  ← 底部固定操作条
└─────────────────────────────────────────────┘
```

- 网格缩略图，hover 放大预览，点选多选。
- 已选区可**拖动排序**（决定最终 deck 页序）。
- "导出选片清单"→ 触发一个 JSON 下载（`{ "slideIds": [...] }`）→ 客户端已有的 `will-download` 拦截器自动接住，进入第 4 步。**这条回传通道客户端侧已经写好了**，只等妙搭页产出这个下载动作。

### 2.5 状态设计（贯穿四步）

每一步都要有这四态，不再只靠日志：

| 态 | 表现 |
|---|---|
| 空 | 浅色插画 / 图标 + 一句引导文案 + 主行动按钮 |
| 进行中 | 骨架屏 / 进度条 / 按钮转圈，禁用重复点击 |
| 成功 | 绿色轻提示（toast）+ 结果摘要（如"导入 66 页"） |
| 失败 | 红色轻提示 + 可读错误原因 + "查看日志"入口 |

### 2.6 文案口吻

正式但不端着，像飞书自己的产品文案。避免"干跑（只打印命令）"这种开发者黑话，改成用户能懂的说法（如"预演（不真正上传）"）。

**不依赖任何账号 / 授权**，纯前端（`desktop/renderer/`）改造。

## 4. 交付线二：选片体验重构（需改妙搭，受账号限制）

### 4.1 卡点（如实说明）

妙搭应用 `app_17eem29n0zk` 的**创建者是 `bytedance_feishu_publish`（ou_9333…）**，而这台机器当前注入的凭证是**戴智（ou_5bfb…）**，且本环境 `auth login` 被硬禁用（strict_mode，外部注入凭证）。因此：

- **我能出完整设计稿**（§2.4 B）。
- **代码落地那一步做不了**，需要你：用 owner 账号在**妙搭 web 编辑态**（`https://miaoda.feishu.cn/app/app_17eem29n0zk`）里改前端，或在能切到该账号的机器上 `lark-cli apps +git-credential-init --app-id app_17eem29n0zk` 后拉源码本地改。

### 4.2 需要妙搭前端做的事（清单，交付给 owner）

1. 用缩略图网格渲染 `slides_catalog` 表（字段已同步：`slide_id / deck_name / title / topic / page_type / thumbnail`）。
2. 多选 + 已选区拖动排序。
3. "导出选片清单"按钮 → 触发下载一个 JSON：`{ "schemaVersion": "...", "slideIds": ["...", ...] }`。
   - 客户端 `will-download` 已就绪，JSON 一落地就自动进第 4 步。
   - 备选：若能拿到 `window.parent`，也可 `postMessage` 回传（客户端可再加通道）。

### 4.3 兜底（无需改妙搭，已实现）

在妙搭还没做导出按钮之前，第 3 步已有**"粘贴 slide_id 列表"兜底**：按顺序粘贴 → 客户端写成 manifest → 直接组合。演示时这条就能兜住。
