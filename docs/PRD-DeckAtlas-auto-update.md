# DeckAtlas 「自动更新」模块 PRD

状态：V1 已实现
版本：v1.0
范围：桌面端自动更新模块、应用内调度与运行记录

## 1. Summary

在 DeckAtlas 桌面端增加一个用户可见、可配置、可暂停的「自动更新」模块。一个计划可以管理多个文件夹，并统一配置文件类型、文件大小范围和执行时间；用户既可以等待计划自动执行，也可以随时点击「立即更新」。DeckAtlas 发现新增或变更文件后，沿现有导入与 LibreOffice PDF 渲染链路更新本地页库。

V1 不安装系统级隐藏任务，不唤醒电脑，也不在错过时间后白天自动补跑。只有 DeckAtlas 仍在运行、设备处于唤醒状态且进入计划时段时才执行。

## 3. Background

### 当前问题

- 手动选择文件夹只解决一次导入，后续新增或修改仍需重复操作。
- 大体量 PPT 渲染耗时明显，白天执行会占用 CPU、磁盘和内存。
- 隐藏的 `launchd`、`cron` 或脚本任务不可见，用户无法确认何时运行、扫描了什么、是否失败。
- 当前已有 46 份、2709 页旧预览等待进入新的 LibreOffice PDF 渲染链路。
- 文件夹同步当前会处理源文件删除；用于自动任务时，直接删除页库内容风险过高。

### 为什么现在做

- 文件夹导入、变更识别、路径移动复用和 LibreOffice PDF 渲染已经可用。
- 当前缺少的是一个面向用户的调度与治理层，而不是另一套导入器。

### 产品原则

1. **用户看得见**：所有计划、运行状态、结果和失败原因都在前端展示。
2. **用户控得住**：可启停、可手动预检、可停止、可修改时间。
3. **默认不破坏**：自动新增和更新；自动删除默认关闭。
4. **错过不偷跑**：错过计划时间后，默认不在白天补跑。
5. **一次只跑一个**：导入、渲染、组合和重复扫描互斥，避免争抢资源。
6. **手动与自动一致**：「立即更新」和定时更新使用同一套文件规则、导入逻辑和运行记录。

## 4. Objective

### 目标

让用户把常用素材目录交给 DeckAtlas 维护，同时保留对范围、时间、资源消耗和数据变化的完整控制。

### Key Results

- 计划执行、暂停、修改和删除操作 100% 可在前端完成。
- 支持一个计划配置多个文件夹，并分别记录每个文件夹的扫描结果。
- 用户可从模块首页、单个计划或单个文件夹立即发起更新。
- DeckAtlas 运行且电脑唤醒时，95% 的计划在设定时间后 2 分钟内开始。
- 不在用户设定的执行窗口外自动启动任务。
- 未变化文件不重复解析和渲染，重复入库率为 0。
- 所有跳过、失败和停止项都有可读原因及重试入口。
- 自动任务不启动 PowerPoint、Chrome 或其他前台窗口。
- 默认设置下，源文件消失不会自动删除页库内容。

## 5. Market Segments

### 核心用户

持续维护大量演示资料的人，需要让本地资料库跟随文件夹变化自动更新。

### 典型任务

- 每天把团队共享目录中的新 PPT 加入页库。
- 用一个计划同时管理核心素材、客户案例和个人草稿等多个目录。
- 在夜间更新修改过的稿件和旧预览。
- 限制超大文件，避免一份稿拖慢整晚任务。
- 只扫描指定格式，不把无关文件带入。
- 第二天查看成功、跳过和失败结果，再决定是否重试。

### 约束

- 仅处理用户主动授权选择的本地文件夹。
- DeckAtlas 退出或电脑睡眠时不执行。
- V1 不负责唤醒电脑，不安装系统后台服务。

## 7. Solution

### 7.1 信息架构

在顶部导航增加独立模块：

**自动更新**
副标题：`目录 · 规则 · 计划`

它不是“导入并渲染”的下一步，而是与“重复管理”同级的长期维护能力。

模块页面分为三个视图：

1. **扫描计划**：查看、新建、编辑、启停计划，以及立即更新全部。
2. **运行中**：查看当前文件、整体进度、资源模式并停止任务。
3. **运行记录**：查看每次结果、失败原因和重试入口。

### 7.2 首页布局

顶部状态带：

- 总开关：`自动更新已开启 / 已暂停`
- 下次运行：`今天 02:30`
- 运行条件：`DeckAtlas 运行中 · 电脑需保持唤醒`
- 主操作：`立即更新全部`
- 次操作：`仅预检`

计划列表使用紧凑表格，不使用嵌套卡片：

| 字段 | 示例 |
| --- | --- |
| 计划名称 | 核心素材库 |
| 文件夹 | 3 个目录 |
| 范围 | 仅 PPTX；10 MB–3 GB |
| 计划 | 每天 02:30 |
| 最近结果 | 新增 3、更新 2、跳过 186、失败 1 |
| 状态 | 开启 / 暂停 / 需授权 |
| 操作 | 立即更新、预检、编辑、暂停、更多 |

展开计划后显示文件夹明细：

| 文件夹 | 最近扫描 | 结果 | 操作 |
| --- | --- | --- | --- |
| 核心素材 | 今天 02:31 | 新增 2、更新 1 | 立即更新 |
| 客户案例 | 今天 02:45 | 无变化 | 立即更新 |
| 个人草稿 | 昨天 02:30 | 1 个超限 | 查看 |

### 7.3 新建或编辑计划

使用右侧抽屉，按用户决策顺序排列。

#### 基本信息

- 计划名称：用户填写；首个文件夹加入后可自动建议名称。
- 扫描文件夹：一个计划可添加多个根目录，也可继续创建多个计划。
- 每个文件夹独立记录名称、路径、授权状态、最近扫描时间和结果。
- 包含子文件夹：每个文件夹单独设置，默认开启。
- 重叠目录：检测父子目录重复，保存前提示并要求移除重复项。
- 不跟随符号链接：固定开启，避免循环和越权。

#### 文件规则

- 文件类型：复选框。
  - PPTX：默认开启。
  - HTML / HTM：默认关闭。
  - HTML Deck ZIP：默认关闭。
- 文件大小范围：
  - 最小值：默认 0 MB，可用于排除过小的测试文件。
  - 最大值：必须设置。
  - 快捷值：100 MB、500 MB、1 GB、3 GB。
  - 最大值默认：3 GB。
  - 不提供“无限制”，始终受系统安全上限约束。
- 规则摘要实时显示，例如：`仅 PPTX · 10 MB–1 GB · 包含子文件夹`。
- 文件大小和扩展名在计算哈希、解析和渲染前完成筛选。
- 自动忽略：
  - Office 临时文件 `~$*`
  - 隐藏文件
  - `.tmp`、`.part` 等未完成文件
- 文件稳定性：大小和修改时间持续 60 秒未变化后才开始导入。

#### 执行计划

- 频率：
  - 手动
  - 每天
  - 指定星期
- 时间：本地时区，默认 `02:30`。
- 执行窗口：默认 `02:00–05:00`。
- 错过计划：
  - 默认：跳过，等待下次。
  - 可选：下次打开 DeckAtlas 时提醒，由用户手动开始。
- 冲突处理：若导入、组合或重复扫描正在运行，则在窗口内等待；超出窗口后跳过。

#### 更新策略

- 新文件：自动加入，默认开启。
- 已修改文件：自动更新，默认开启。
- 路径移动：复用原索引并更新路径，默认开启。
- 修复旧预览：使用 LibreOffice PDF 链路重试，默认开启。
- 源文件消失：
  - 默认：标记“源文件不可用”，保留页库内容。
  - 高级选项：同步移出页库，需要二次确认。

#### 资源与提醒

- 后台低资源模式：默认开启，V1 固定单任务串行。
- 完成后系统通知：默认关闭，开启时再申请通知权限。
- 失败时在模块导航显示提示点。

### 7.4 核心用户流程

#### 首次创建

1. 用户进入「自动更新」。
2. 点击「新建扫描计划」。
3. 添加一个或多个文件夹，并设置类型、大小和时间。
4. 点击「预检」。
5. 页面按文件夹展示预计新增、更新、旧预览修复、超限和不支持文件。
6. 用户确认后保存并开启计划。

#### 立即更新

1. 用户点击页面顶部「立即更新全部」、计划行「立即更新」，或文件夹行「立即更新」。
2. DeckAtlas 立即执行一次预检，并在确认面板展示影响范围。
3. 用户确认后立刻更新，不受定时时间限制。
4. 立即更新仍遵守文件类型、大小范围、重复目录、文件稳定性和删除策略。
5. 如果有其他重任务，用户可以选择排队或取消，不允许静默并发。
6. 运行记录标记触发方式为“手动立即更新”。

#### 自动执行

1. DeckAtlas 每分钟检查是否有到期计划。
2. 进入执行窗口且当前无重任务时，创建一次运行记录。
3. 逐个文件夹读取文件元数据，先按扩展名和大小筛选，再仅对新增或变化文件计算哈希。
4. 逐文件导入并沿 `PPTX → LibreOffice PDF → 图片` 渲染。
5. 每完成一个文件即落盘；中断后不重复已完成文件。
6. 执行结束后更新页库，并在模块中展示摘要。

#### 用户停止

- 点击「停止任务」后，不再开始下一份文件。
- 当前文件完成安全清理后结束。
- 已完成内容保留，未开始内容显示“已取消”。
- 用户可以从失败或取消项继续。

### 7.5 运行状态

计划状态：

- 开启
- 暂停
- 需重新授权文件夹
- 配置错误

运行状态：

- 等待执行窗口
- 等待其他任务
- 预检中
- 扫描中
- 导入中
- 渲染中
- 正在停止
- 已完成
- 部分成功
- 已失败
- 已取消
- 已错过

运行中页面必须显示：

- 当前计划、当前文件夹与总文件夹进度。
- 当前文件名和文件序号。
- 当前页数进度。
- 已新增、更新、跳过、失败数量。
- 开始时间、已用时间。
- 「停止任务」按钮。

### 7.6 运行记录

每次记录包含：

- 计划名称、触发方式、开始和结束时间。
- 各文件夹的扫描时间、文件统计和授权状态。
- 总文件数、总页数、耗时。
- 新增、更新、移动、未变化、超限、不支持、失败、取消数量。
- 每个失败文件的可读原因。
- `重试失败项`、`查看文件位置`、`查看详细日志`。

历史默认保留 30 天；删除历史不删除页库内容。

### 7.7 关键交互规则

- 保存计划前必须先完成一次预检。
- 计划关闭时绝不自动执行。
- 「立即更新」不受时间窗口限制，但自动预检后必须确认影响范围。
- 页面顶部可更新全部启用计划；计划行和文件夹行可只更新当前范围。
- 编辑运行中的计划只影响下一次执行。
- 同一计划中的重叠目录在保存前拦截；跨计划重复文件按真实路径去重，只处理一次。
- 自动任务不能弹出 PowerPoint、LibreOffice、Chrome 或密码窗口。
- 图片 URL 必须带缓存版本，任务完成后前端自动刷新受影响页面。

### 7.8 技术方案

#### 调度位置

调度器放在 Electron 主进程，不注册 `launchd`、`cron` 或独立系统服务。

- DeckAtlas 进程退出：调度停止。
- 电脑睡眠：调度暂停。
- 唤醒后已超出执行窗口：记录“已错过”，不补跑。
- 窗口关闭但 DeckAtlas 仍在 Dock 运行：允许执行，并在页面中明确说明。

#### 后端复用

- 扫描：复用 `discover_paths` 和现有文件类型识别。
- 导入：复用目录同步、内容哈希和移动复用。
- 渲染：固定使用 LibreOffice PDF 路线。
- 预检：新增只读模式，不写数据库、不生成图片。
- 自动删除：从现有同步逻辑中拆为独立策略，默认不执行。

#### 与现有系统衔接

- **导入并渲染**：保留现有手动导入；文件夹导入成功后增加「保存为自动更新计划」，不要求重新选择目录。
- **页库**：任务完成后局部刷新受影响文件和图片 URL，不强制整库重载或重启应用。
- **选片**：版本未变化的页面保持已选状态；被更新或移除的页面明确提示，不静默替换选片。
- **组合导出**：自动更新与组合任务互斥；组合期间到期计划进入等待，避免源版本变化。
- **重复管理**：更新完成后复用现有指纹；重复扫描不与自动更新并发。
- **现有索引**：复用 canonical path、SHA-256、版本和移动识别，不生成第二套页库。
- **当前旧预览**：首次运行把 46 份、2709 页旧缓存列入“待修复预览”，由用户在预检中确认。

#### 数据模型

建议新增：

- `scan_plans`
  - 名称、启停状态、时间、执行窗口、文件类型、最小/最大大小、更新策略。
- `scan_plan_roots`
  - 计划 ID、文件夹名称、路径、递归设置、授权状态、最近扫描结果。
- `scan_runs`
  - 触发方式、执行范围、状态、统计、开始和结束时间。
- `scan_run_items`
  - 根目录 ID、文件路径、筛选结果、动作、页数、耗时、错误原因。

#### Electron 接口

- `scan-plan:list`
- `scan-plan:create`
- `scan-plan:update`
- `scan-plan:delete`
- `scan-plan:preview`
- `scan-plan:run`
- `scan-plan:run-all`
- `scan-root:run`
- `scan-run:current`
- `scan-run:stop`
- `scan-run:history`
- `scan-run:retry`

#### 并发与恢复

- 全局只允许一个重任务。
- 计划运行前获取数据库任务锁。
- 每个文件完成后写入运行记录。
- 应用异常退出后，下次启动把未结束任务标记为“已中断”，由用户决定是否继续。

### 7.9 异常处理

| 场景 | 产品行为 |
| --- | --- |
| 文件夹不存在 | 计划暂停并标记“需重新授权” |
| 文件夹互相包含 | 保存前拦截并指出重叠路径 |
| 文件正在复制 | 延迟到稳定 60 秒后处理 |
| 文件小于最小值 | 跳过并记录“小于筛选范围” |
| 文件超过上限 | 跳过并显示实际大小 |
| 类型不支持 | 跳过并说明支持范围 |
| PPTX 损坏 | 单文件失败，继续后续文件 |
| 真实外链媒体 | 保留旧预览并提示先嵌入资源 |
| LibreOffice 失败 | 记录失败，不自动切回低保真浏览器渲染 |
| 应用退出 | 当前任务安全停止并记录中断 |
| 电脑睡眠 | 暂停；超出窗口后不补跑 |
| 源文件删除 | 默认只标记，不删除页库 |

### 7.10 Assumptions

- 用户愿意让 DeckAtlas 在计划时段保持运行。
- 夜间串行渲染对设备资源影响可接受。
- 大部分资料更新是新增和修改，不要求秒级实时监听。
- 用户更重视可控和可解释，而不是“无感但不可见”的系统后台能力。

### 7.11 Non-goals

- V1 不安装系统级后台服务。
- V1 不唤醒或自动开机。
- V1 不做文件系统实时监听。
- V1 不自动删除页库内容。
- V1 不使用 Microsoft PowerPoint 前台自动化。
- V1 不上传源文件或扫描结果到云端。

## 8. Release

### V1：可控的每日自动更新

一个短迭代完成：

- 自动更新独立模块。
- 扫描计划增删改查。
- 单个计划配置多个文件夹并保留文件夹级记录。
- 文件类型、最小/最大大小、时间和执行窗口配置。
- 预检、启停、立即更新全部、更新单计划、更新单文件夹和停止。
- 新增、修改、移动及旧预览修复。
- 运行记录和失败重试。
- 与手动导入、页库、选片、组合和重复管理衔接。
- 应用内调度，不安装系统任务。

### V1.1：效率与提醒

- 指定星期。
- 完成通知。
- 更细的资源限制。
- 多计划冲突排序。
- 用户确认后的删除同步。

### V2：可选系统级运行

只有用户明确开启时，才提供“DeckAtlas 退出后仍运行”的系统服务模式，并在前端持续展示注册状态、下次运行和一键卸载。该能力不进入 V1。

### 验收标准

1. 用户可以在一个计划中添加至少 3 个文件夹，并分别查看最近扫描结果。
2. 用户可以创建“每天 02:30、仅 PPTX、10 MB–3 GB”的规则。
3. 用户可以立即更新全部计划、一个计划或其中一个文件夹。
4. 立即更新会先展示影响范围，确认后才开始。
5. 保存前可以按文件夹预览新增、修改、旧预览、低于下限、超限和不支持数量。
6. PPTX、HTML / HTM 和 HTML Deck ZIP 可以独立勾选，未勾选格式不会计算哈希。
7. 重叠文件夹会在保存前被识别并阻止重复扫描。
8. 关闭计划后，连续跨过两个计划时间也不会产生运行记录。
9. DeckAtlas 运行且设备唤醒时，计划在设定时间后 2 分钟内启动。
10. 计划错过执行窗口后不会在白天自动开始。
11. 自动任务期间不出现 PowerPoint、LibreOffice、Chrome 或密码窗口。
12. 未变化文件不重新渲染。
13. 文件处理失败不会阻塞后续文件。
14. 停止任务后不再启动下一文件，已完成结果保留。
15. 删除源文件默认不会删除页库内容。
16. 所有结果可按计划、文件夹和文件追踪，并可单独重试失败项。
17. 更新期间不会与组合导出或重复扫描并发。
18. 旧图片被替换后，前端不依赖重启即可显示新缓存版本。
